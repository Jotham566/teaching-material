# DA22 Instructor guide: Report and handover

Private. Keep this file out of the student folder.

**Objective.** By the end: you can hand over a project that another person can open, rerun and check.

**Question of the day.** Does everything I share open, rerun and agree with itself?

**Where this is used.** Before a team hands work over, they restart everything and run it from the top to prove it works. A tidy handover saves other people days. Does your notebook run from the first cell to the last?

Prerequisite: DA21 Build and check the chart report.

## The 180 minutes

| Minutes | Activity |
|---|---|
| 15 | recall, then the handover checklist |
| 60 | rerun from a restarted kernel and repair |
| 15 | break away from screens |
| 50 | write and export the report |
| 25 | individual check and share |
| 15 | feedback, then save |

Where it overruns: Check each learner's folder arrived. A file on a laptop has not been shared.

## Make: reference

Checklist: the notebook reruns from a restarted kernel; the cleaning log counts each row removed; the data dictionary covers every column used; each finding in the report has a number in an output cell; the report states the invented or licensed data source and its limits; the log records any permitted AI help or says No AI assistance used; every file opens after being reopened.

Build log entry to look for: All five files saved together and reopened, and totals in the report that agree with the notebook.

## Misconceptions to listen for

- A polished picture is enough evidence.
- A saved file has been shared.
- Restarting the kernel is only for beginners.

## Questions to ask, with expected answers

- How do you know your report matches your notebook? Expected: Each number in the report is copied from an output cell that reruns from the top.
- What did you decide not to claim? Expected: A limitation named in the report, such as no costs so no profit.

## Online version

For a hybrid group. The live class is 90 minutes on video with screen sharing. The learner finishes the build in their own time, about an hour. The full rules are in handbook/HYBRID_DELIVERY.md.

### Live clock, 90 minutes

| Minutes | Activity |
|---|---|
| 5 | Recall: three questions on paper, then say the answers aloud |
| 35 | Read the brief together on the shared screen, then the first build step. Each learner shares their screen in turn. |
| 5 | Break away from the screen |
| 35 | Learners keep building. The instructor visits each learner by screen share, about seven minutes each. |
| 10 | Close: say the exit sentence aloud, then the rest of the build task is set |

### After-class build task, about an hour

1. Make: Restart the kernel and run all cells from the top. Confirm every number in the report appears in an output. Write the one-page report: question, data, method, three findings with their values, one recommendation and one limitation. Export it to PDF and reopen it. Save project.ipynb, cleaning_log.md, your data dictionary, report.pdf or report.docx and AI_USE_LOG.md together in your project folder, and share the folder by the route in START_HERE.md. Keep personal information out of every file.

When you finish, write two sentences: what you changed and how you checked it. Add a build log entry. Send a photo of your work or the notebook by the route the organiser sets, before the next class.

Look at what each of the five learners saved and note one strength and one next step for each. Share them kindly and privately. Nothing is scored or ranked. Visit every learner, not only volunteers.
