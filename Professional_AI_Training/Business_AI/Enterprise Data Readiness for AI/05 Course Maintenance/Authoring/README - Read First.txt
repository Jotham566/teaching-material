AUTHORING SOURCES: HOW THE COURSE IS BUILT

Everything participants and the tutor see is generated from files in this folder. Edit a source, rebuild, check.

Sources
  Build/curriculum.py             the 12 sessions: titles, questions, results, outcomes, topics, the tool and licence lists
  Build/curriculum.json           the same sessions in shorter wording, read by make_roadmap.py and make_report.js
  Content/sNN.json                the content of session NN: vocabulary, slides, speaker notes, workshop tasks with worked examples, team notebook cells
  AUTHOR BRIEF.md and REVIEW BRIEF.md   the instructions the sessions were written and reviewed under

Scripts in Build
  build_teaching_data.py          generates the Kitara tables, documents and answer_key.json from a seed (do not run on its own, see below)
  build_extra_data.py             generates the extra Kitara files
  kitara_*.py                     document text, names, questions, tables and templates used by the generators
  kitara_search.py                the search toolkit that sessions 5 to 7 import; copied into the data folder and the zip
  figs.py                         draws the figures into figs_cache
  deckkit.py                      the slide engine
  build_course.py                 data, check N, build N or build all
  check_course.py                 course-level checks (vocabulary, repeated sentences, figure names, titles)
  export_docs_data.py             writes docs_data.json from curriculum.py, Content and the built decks
  make_docs.js                    the Participant Workbook, Course Plan and Tutor Guide, Glossary and Setup Guide
  make_roadmap.py                 the one-page roadmap (pptx and pdf)
  make_playback_checklist.py      the Playback and Rehearsal Checklist
  make_report.js                  the Benchmark and Design Report
  make_start_here.py              00 Start Here.txt and Verification Record.txt (counts come from docs_data.json)

Rebuild everything, in this order (run from the Build folder)
  1 python3 build_course.py data          regenerates the data, extra data, kitara_search.py copy, data.zip and figures
  2 python3 build_course.py build all     every deck, student notebook and solution notebook
  3 python3 check_course.py               must report no course-level problems
  4 python3 export_docs_data.py           counts and content for the documents
  5 node make_docs.js                     four Word documents
  6 python3 make_roadmap.py
  7 python3 make_playback_checklist.py
  8 node make_report.js
  9 python3 make_start_here.py
build_teaching_data.py writes data.zip without kitara_search.py. Use build_course.py data, which makes the zip last.
Then run the PowerPoint validator on each deck, and python3 "04 Facilitator Materials/run_all_labs.py" "04 Facilitator Materials/Lab Solutions" "03 Learner Materials/Practice Files/data" --allow-missing-libs from the course folder.

Fixing wording
  Wording in a Word document, the roadmap, the checklist or Start Here is fixed in its generator (make_docs.js, curriculum.py, make_roadmap.py, make_playback_checklist.py, make_report.js, make_start_here.py) or in the Content file, never in the generated file. A failing notebook is fixed in the Content JSON and rebuilt with build_course.py build N.

Design system
  ink 1F2328, body 3B4046, soft 6A6F75, hairline C9C5BC, accent B04A2B. Cambria headings, Calibri text, Courier New code. Type and hairlines with almost no fill.

What check does
  fits every slide, lints every speaker note, runs every pandas, numpy, matplotlib and SQL block on a slide or in a notebook against the real data and compares the slide output, and checks structure (recall slide first, a trap, a lab, an exit check, a summary, at least five animated slides, vocabulary count).
  Code that needs the heavy libraries is syntax-checked only on a machine without them.

Git
  Commit Content, Build, the data folder and data.zip. figs_cache is regenerated by build_course.py data.
