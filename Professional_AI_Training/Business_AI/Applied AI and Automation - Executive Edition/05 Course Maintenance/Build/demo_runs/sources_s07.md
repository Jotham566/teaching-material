# Sources checked for Session 7 (checked 6 November 2026)

- OSI, The Open Source AI Definition 1.0, https://opensource.org/ai/open-source-ai-definition (fetched 6 Nov 2026). Says an Open Source AI system grants four freedoms (use for any purpose without asking permission, study, modify, share) and that the preferred form for modifying a system must include: data information ("sufficiently detailed information about the data used to train the system", enough for a skilled person to build a substantially equivalent system; this is information, not necessarily the data itself), the complete source code used to train and run the system, and the model parameters (weights), each under OSI-approved terms. The page shows no release date; the release was October 2024 per the Session brief and press coverage (InfoQ, November 2024); the slides say "version 1.0, 2024".
- OSI, "Meta's LLaMa license is not Open Source", https://opensource.org/blog/metas-llama-2-license-is-not-open-source, dated 20 July 2023 (about Llama 2). Reason given: the licence limits some users and some fields of use, which the Open Source Definition does not allow.
- It's FOSS, 18 October 2024, https://itsfoss.com/news/osi-meta-ai/ (secondary): reports OSI's executive director told the Financial Times that Meta's use of "open source" for Llama confuses users, and that the Llama licence restricts use too much to meet the Open Source Definition. (Superseded: the February 2025 OSI statement is now confirmed, see below.)
- Llama 3.2 Community Licence text, https://huggingface.co/meta-llama/Llama-3.2-1B/blob/main/LICENSE.txt (fetched 6 Nov 2026; summary by the fetch tool, read it in full before quoting): a company whose products had more than 700 million monthly active users in the month before the release date must request a licence from Meta; "Built with Llama" display when distributing; models made with Llama outputs and distributed must start their name with "Llama"; use must follow the Acceptable Use Policy; California law. The slides say "the Llama 3.2 licence" and tell the lecturer to check the version in force.
- Hugging Face model API for HuggingFaceTB/SmolLM2-135M-Instruct, https://huggingface.co/api/models/HuggingFaceTB/SmolLM2-135M-Instruct?blobs=true (queried 6 Nov 2026): licence apache-2.0; model.safetensors 269,060,552 bytes; ONNX files model.onnx 540,345,794, model_fp16.onnx 270,267,067, model_int8.onnx 137,147,867, model_q4.onnx 182,068,553, model_q4f16.onnx 117,691,126, model_bnb4.onnx 175,434,623.
- Hugging Face model API for bartowski/SmolLM2-135M-Instruct-GGUF (community conversion, licence apache-2.0), https://huggingface.co/api/models/bartowski/SmolLM2-135M-Instruct-GGUF?blobs=true (queried 6 Nov 2026): f16 270,885,952; Q8_0 144,811,360; Q6_K 138,383,200; Q5_K_M 112,103,776; Q4_K_M 105,454,432; Q4_0 91,893,088 bytes.
- Safetensors, https://huggingface.co/docs/safetensors/index: "a new simple format for storing tensors safely (as opposed to pickle) and that is still fast".
- GGUF, https://huggingface.co/docs/hub/en/gguf: a binary format for quick loading, made by the developer of llama.cpp; unlike tensor-only formats such as safetensors, GGUF holds both tensors and a standard set of metadata; the page lists quantisation types (F32, F16, Q8_0, Q4_K and others) inside it.
- ONNX, https://onnx.ai/: an open standard for machine learning models, with a shared set of operators and a common file format, so a model built in one framework can run in different tools and runtimes.
- Not claimed anywhere: prices of any rented or hosted model, hardware prices, Llama 4 licence terms, the contents of any closed model.
- OSI blog, "Meta's Llama license is still not Open Source", https://opensource.org/blog/metas-llama-license-is-still-not-open-source (fetched 6 Nov 2026), dated 18 February 2025: says Llama 3.x is still not Open Source, citing failures against Open Source Definition points on use for any purpose, discrimination and fields of endeavour. This CONFIRMS the February 2025 OSI statement. It says the Llama analysis does not need the OSAID 1.0. The slide wording "The OSI has said that does not meet its open source definition" is supported (the Open Source Definition, not the AI definition).
