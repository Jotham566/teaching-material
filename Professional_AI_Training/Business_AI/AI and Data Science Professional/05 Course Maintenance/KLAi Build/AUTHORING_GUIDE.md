## What changed and why (lecturer request, 4 Nov 2026)
1. **KLAi branding**: black, white, red, gold, Lato, the KLAi logo. The kit does this for you. Do not use the old clay/charcoal look.
2. **Concepts first, then the lab.** The deck has a concepts half (no laptops open, diagrams, plain words, code shown only as a read-aloud recipe), then a divider slide whose title starts with `Part 2`, then a few lab slides, then the learner works in the notebook (or the Google Sheet) for 45 minutes. The lecturer switches from slides to the notebook ONCE. Old decks mixed demonstration code and lab inside the slides: move the demonstrations into concepts (as picture plus recipe) and the work into the lab.
3. **Industry terms, not over-simplified names.** Old slides said "grain" for one row, "wobble", "the misses", "a hidden third factor" and so on. Use the real term (record or observation, sampling variability and standard error, residuals, confounder ...) as the NAME, then explain it in plain words beside it. See TERMS.md; extend it by adding terms to your final report if you need new ones. Excel stays the anchor: the Excel word first, then the industry term on the same slide.
4. **Value and usefulness.** Each session answers "what can I do at work on Monday?". One slide in the concepts half titled "Where you will use this at work: ..." (East African business examples with the real job tasks and the real tool names an employer uses: SQL at a bank, pandas in a ministry report, scikit-learn in a credit team, Power BI or Excel handoff, etc.), and the lab ends with a deliverable the learner keeps (a cleaned file, a notebook, a one-page finding).
5. **Self-study clarity.** Decks are shared as PDFs and learners revise from them WITHOUT notes. Full plain sentences, every term defined where it first appears, units, say what the picture shows, no pronoun without a clear noun. Ask of every sentence: could a bright adult who knows Excel but not statistics or code misread this?

## The lab
**Python sessions** (`content/labs/sNN_nb.py`): `TITLE = 'Short title'` and `build(solution: bool) -> nb.Notebook` (see `kit/nb.py`, `kit/make_notebooks.py`). First cell `nb.data_setup()` (puts the course data next to the notebook in Colab), then `nb.check_setup()`. Rhythm per step: `nb.step`, `nb.predict`, `nb.read`, `nb.change`; the learner version holds `answer = None  # your code here` (one-line hint in plain words) where the solution holds the model answer; `check('label', value, expected, tol)` after each answer, `show_checks()` last. The solution must end 'All N checks pass'; the learner version must not. Expected values come from numbers computed in your session file (pandas on the real data), never typed from memory. Conventional variable names (TERMS.md). Plain-words comments. 7 to 14 code cells. The old notebook cells (old JSON `lab.cells`, with `starter` and asserts) are a good source of tasks; keep their task sequence unless a better one is obvious, but add the PREDICT, READ and CHANGE prompts.
**Libraries this sandbox lacks** (SciPy, statsmodels, torch, TensorFlow, transformers, sentence-transformers, streamlit; scikit-learn only partly via `ref/sklearn`): list them in a module constant `NEEDS = ['scipy', 'statsmodels']`. The runner then proves only that every cell compiles and prints UNVERIFIED. For those labs the expected numbers must still be computed independently with numpy/pandas in your session file (the checks compare the library result with that number). State in your report which cells could not run here. Never show a library output on a slide that you did not compute with an independent method in this sandbox.
**Sheets sessions**: `sheet_tasks` as above, working on `lakeside_for_sheets.xlsx` (tabs: orders, order_lines, products, branches, customers, branch_weeks and others, see the data dictionary). Write the answers with real numbers and the exact Sheets formulas.

## Facts discipline
Same rules as the Mathematics course. External facts (laws, vendor limits, certifications, job-market claims) only if the old content had them from a researched source, or you can state them as stable, hedged ('my understanding is', 'check the current terms'). ## Notes (spoken script)
Every slide: first-person spoken notes, 45 to 150 words (aim 70 to 120), ending on a question where natural. No stage directions, no 'click', no brackets. House style: no 'X, not Y' constructions, no em or en dashes, no 'honestly', 'genuinely', 'straightforward', 'journey', 'leverage', 'delve', 'unlock'; no he or she for learners; address them as 'you'. The notes must match what the slide says, including the industry term.
